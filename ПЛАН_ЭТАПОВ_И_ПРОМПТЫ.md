## 2. Как работать (ритуал)

1. Открой **новый чат** DSH, рабочая папка **G:\wakeproof**, модель и effort — из таблицы.
2. Вставь **ШАПКУ + текст этапа** одним сообщением.
3. Дождись, пока агент соберёт проект и закоммитит. Он сам пишет в конце, что проверить.
4. Проверь на эмуляторе (можно попросить агента самого поставить APK: `adb install -r app/build/outputs/apk/debug/app-debug.apk`).
5. Все **правки по результатам проверки — в том же чате** (контекст уже загружен). Новый чат — только для нового этапа.
6. В конце каждого этапа агент делает git-коммит. Если этап испорчен: `git log --oneline`, найди коммит последнего хорошего этапа, откатись (`git reset --hard <hash>`).

**Промпт для исправления бага (в том же чате этапа):**

```
Проблема после проверки этапа N.
Шаги: <что сделал на эмуляторе>.
Ожидал по ТЗ: <раздел ТЗ, например 4.3>.
Получил: <что произошло>.
Исправь минимально, ничего лишнего не трогай, пересобери и закоммить «Этап N fix: ...».
```

Если чат этапа «захлебнулся» — открой новый с ШАПКОЙ + этим шаблоном:
«Продолжение этапа N. Посмотри git log и код. Проблема: … Ожидалось по ТЗ <раздел>: …»

### ЭТАП 2 — Планирование и звонок, базовый (glm-5.3, max)

```
Реализуй фактическое срабатывание будильника по ТЗ 4.1.3 и разделу 2. Это самый капризный этап — AlarmManager, foreground service, локскрин. Задачи на экране — следующий этап, сейчас временная кнопка «Выключить».

ЧТО СДЕЛАТЬ:
1. AlarmScheduler: расчёт следующего срабатывания (дни недели, переход через полночь), AlarmManager.setAlarmClock() + AlarmClockInfo. Отмена при выключении/удалении будильника. Перепланирование при любом изменении.
2. BroadcastReceiver'ы: AlarmReceiver (старт звонка), BootReceiver (BOOT_COMPLETED — перепланировать все включённые), TimeChangedReceiver (TIMEZONE_CHANGED, TIME_SET — перепланировать). Раздел 5 ТЗ.
3. RingingService — foreground service ТИП mediaPlayback (FOREGROUND_SERVICE_MEDIA_PLAYBACK для Android 14+): играет звук через AudioAttributes USAGE_ALARM, нарастание громкости 20%→100% за 60 с линейно (ТЗ 4.1.5), шаг 5% каждые 3 с, вибрация синхронно. Звук — положи в res/raw валидную заготовку (свободный CC0 или синтезированный); выбор звука в UI не нужен.
4. Каналы уведомлений: «Будильник», отдельное уведомление FGS.
5. RingingActivity: full-screen intent (USE_FULL_SCREEN_INTENT), setShowWhenLocked(true), setTurnScreenOn(true), показывается поверх блокировки. Крупные часы, название будильника, ВРЕМЕННАЯ кнопка «Выключить». BackHandler — назад не выходит. Свайпом/домой не закрыть: если активити потеряло фокус — сервис возвращает full-screen intent в течение 2 секунд и ускоряет рост громкости (ТЗ 4.1.3, 4.1.5).
6. Остановка: кнопка «Выключить» → stopService, отмена задачи, уведомление убрать. Перепланировать будильник на следующий день.

РАЗРЕШЁННЫЕ ЗАВИСИМОСТИ: новых нет.

КРИТЕРИИ ГОТОВНОСТИ: будильник на +2 минуты срабатывает при заблокированном эмуляторе (экран гасит adb: `adb shell input keyevent 26`); звук нарастает; «Выключить» работает; после перезагрузки эмулятора будильник не теряется; значок будильника в статус-баре присутствует при активном расписании.
```

### ЭТАП 4 — Экран звонка с задачами + аварийный выход (glm-5.3, high)

```
Интегрируй движок задач в экран звонка (этапы 2+3) и сделай аварийный выход по ТЗ 4.1.3, 4.1.4.

ЧТО СДЕЛАТЬ:
1. Вместо кнопки «Выключить» — последовательность задач из SessionTaskPlanner (типы и количество из настроек будильника). UI каждого типа:
   - математика: крупный пример, большая цифровая клавиатура, поле ответа, «OK»; нужно N правильных ответов подряд (по сложности), ошибка сбрасывает серию внутри задачи;
   - память: сетка 4 больших цветных кнопок, анимация вспышки последовательности, потом повтор пользователем;
   - Stroop: слово крупным шрифтом, напечатанное цветом чернил, снизу 4 кнопки с названиями цветов; нажать цвет ЧЕРНИЛ.
2. Прогресс сверху: «Задача 1 из 2», счётчик ошибок. Одна задача на экране единовременно.
3. TaskSessionRecorder: пишет в Room TaskSession (alarmId, startedAt, finishedAt, result: CLEAN/SNOOZED/EMERGENCY/MISSED/REECK_FAILED — пока CLEAN/EMERGENCY, mistakes, durationMs, taskResults). Миграция базы.
4. После успешного решения всех задач — экран сводки по ТЗ 4.1.3: «☀️ Доброе утро! ⏱ время, ошибки» (серия и контрольный звонок — следующие этапы, оставь места под них) → кнопка «Закрыть» останавливает сервис и перепланирует будильник.
5. Аварийный выход по ТЗ 4.1.4:
   - скрытая зона: маленький прозрачный угол экрана (≈48dp), долгое нажатие 5 секунд с тонкой полоской прогресса;
   - словарь ~200 русских слов в strings.xml; фраза из 4 слов генерируется ОДИН раз при первом запуске, хранится локально (DataStore или Room);
   - экран ввода фразы: поле ввода + САМА ФРАЗА мелким серым шрифтом как подсказка (принцип: неудобно, но тупика нет);
   - экран «Настройки → Аварийный выход»: посмотреть фразу, перегенерировать;
   - успех → звонок останавливается, сессия помечается EMERGENCY, в Room пишется запись аварийного выхода (время, будильник, сколько задач решено, длительность).

КРИТЕРИИ ГОТОВНОСТИ: будильник выключается ТОЛЬКО решением задач или аварийным выходом; все 3 типа задач играбельны; лонг-пресс 5 с → фраза → выход; в базе видны сессии.
```

### ЭТАП 5 — Snooze-политики, хардкор, серия (glm-5.3-flash, средний)

```
Реализуй snooze по ТЗ 4.1.2, поведение хардкора (ТЗ 4.2.1) и серию по ТЗ 4.4.

ЧТО СДЕЛАТЬ:
1. Snooze:
   - на экране звонка кнопка «+10 мин» появляется ТОЛЬКО если политика будильника ≠ «запрещён»; в хардкоре — никогда;
   - snooze = перепланирование звонка через 10 минут (константа), лимит 1 раз на срабатывание;
   - «один раз» — повторный звонок с теми же параметрами; «один раз с усложнением» — +1 задача (максимум 4 задачи за сессию; если уже 4 — режим сложности на уровень выше: лёгкий→средний→хардкор);
   - финальный результат сессии при snooze помечается SNOOZED.
2. Хардкор (активируй поведение): 4 задачи, нарастание громкости выключено (100% сразу), snooze недоступен, контрольную проверку будет нельзя отключить (этап 6).
3. Серия (streak) по ТЗ 4.4:
   - StreakCalculator по истории TaskSession: серия = число подряд CLEAN-утр от конца истории; сброс при SNOOZED / EMERGENCY / MISSED / RECHECK_FAILED;
   - отображение: главный экран под ближайшим будильником («🔥 12»), экран сводки после выключения;
   - экран «Статистика»: текущая серия + рекордная серия.
4. Unit-тесты: snooze-переходы (политики, +1 задача, лимит 4 → уровень выше, сброс лимита), начисление и все варианты сброса серии (раздел 8 ТЗ п.2, п.4).

КРИТЕРИИ ГОТОВНОСТИ: при запрещённом snooze кнопки нет; «один раз» даёт повтор без последствий; «с усложнением» добавляет задачу; серия на главном экране обновляется после утр.
```

### ЭТАП 6 — Контрольная проверка «через 10 минут» (glm-5.3, high)

```
Реализуй контрольную проверку по ТЗ 4.3. Решает проблему «выключил и уснул обратно».

ЧТО СДЕЛАТЬ:
1. После успешного выключения будильника (если isRecheckEnabled): планирование контрольного звонка через recheckDelayMin (5/10/15) тем же AlarmManager.setAlarmClock (отдельный requestCode), флаг recheck в данных будильника.
2. Постоянное уведомление после выключения: «✅ Контрольный звонок через X мин» с кнопкой «Отменить».
3. Контрольный звонок: тихий — 30% громкости, короткий сигнал, БЕЗ нарастания; экран поверх блокировки с ОДНОЙ лёгкой задачей (математика EASY, 1 ответ); таймер 60 секунд на решение.
4. Исходы:
   - успех за 60 с → отмена уведомления, в сессию recheckPassed=true;
   - игнор или провал → ПОЛНЫЙ повторный звонок: 100% громкости, +1 задача, snooze недоступен; максимум 2 повторных звонка, дальше звонок звучит до решения (аварийный выход доступен всегда);
   - «Отменить» из уведомления → экран с 1 лёгкой задачей; решил → отмена засчитана как пройденная (серия не страдает, пометка «отменена задачей»).
5. Влияние на серию: RECHECK_FAILED (дошло до повторного полного звонка) сбрасывает серию; отмена задачей и успех — нет.
6. В хардкоре: switch контрольной проверки в редакторе задизейблен (отключить нельзя, менять интервал можно).
7. Unit-тесты: планирование/отмена/провал/лимит повторов (раздел 8 ТЗ п.3).

КРИТЕРИИ ГОТОВНОСТИ: после выключения будильника с интервалом 5 мин через 5 мин приходит тихий звонок с 1 задачей; если 60 с не решать — полный повторный звонок громче и с лишней задачей; «Отменить» из уведомления требует 1 задачу.
```
